LawGoat at Belva

Building LawGoat: the design system, the AI surfaces, and the code, all from one chair.

Role Head of Product Design
Year 2024 — Ongoing
Stack Cursor · VS Code · Claude · HTMX · Tailwind · Python

LawGoat is Belva’s AI platform for law firms: one workspace where attorneys talk to clients, review documents, and automate the repetitive parts of intake, scheduling, and case management.

I joined as the first product designer and built the design language, component library, and most of the production UI from scratch. Three pieces of that work below.

01 — Design System

A component library, in production from week one.

Engineering was already shipping UI before I arrived, so every day without a system meant more inconsistency to clean up later. I built one in flight: modeling components in Figma, then translating them into HTMX and Tailwind with Claude inside Cursor, on the same branch, same PR, same review.

The payoff is zero drift between design files and production code. The library covers buttons, inputs, tables, modals, toasts, and LawGoat-specific patterns like case cards, AI message blocks, and document viewers.

The fastest way to ship a design system is to be the one writing the code.
02 — AI Chat UX

Designing trust into a conversational AI for attorneys.

Attorneys don’t trust black boxes; a generic chatbot would’ve been dismissed in the first demo. Every AI answer in LawGoat is grounded in the specific case, with dates, providers, and documents pulled straight from the file, and every claim it makes links back to a source document instead of a vague summary.

The case summary view takes this further, with a running analysis that separates Risks from Opportunities into plain, color-coded blocks, so an attorney can scan a case’s exposure and leverage instead of re-reading the whole file.

03 — Case Management

A workflow flexible enough for every practice area.

Legal workflows are non-linear and vary wildly between practice areas, and a rigid pipeline would’ve broken for half our users. The case-management surface is a configurable table with stages defined per practice area, drag-to-reorder columns and rows, and a document system that keeps every file (medical records, correspondence, evidence) tagged and searchable against the case it belongs to.
