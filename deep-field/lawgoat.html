I joined as the first product designer and built the design language, component library, and most of the production UI from zero. Three pieces of work below.

01 — Design System

A component library, in production from week one.

Engineering was already shipping UI before I arrived. Every day without a system was another round of inconsistency to clean up later. So I built one in flight — modeling components in Figma using Figma MCP, then translating them to React using Claude CLI inside Cursor on the same branch, same PR, same review.

Result: zero drift between design files and production code. The library covers buttons, inputs, tables, modals, toasts, and the LawGoat-specific patterns — case cards, AI message blocks, document viewers.

Component library — Figma source
The fastest way to ship a design system is to be the one writing the code.
02 — AI Chat UX

Designing trust into a conversational AI for attorneys.

Attorneys don’t trust black boxes. A generic chatbot would have been dismissed in the first demo. Every AI response in LawGoat surfaces its sources inline, lets users expand the underlying citations, and tags responses with confidence indicators when the model is operating outside its training distribution.

The trust signals were validated through testing with practicing attorneys before any of it shipped.

AI chat — citation expansion
03 — Case Management

A workflow flexible enough for every practice area.

Legal workflows are non-linear and vary wildly between practice areas. A rigid pipeline would have broken for half our users. The case-management surface is a kanban-style board with configurable stages per practice area, automated task assignment on status changes, and a document tagging system that links files to specific case milestones.
